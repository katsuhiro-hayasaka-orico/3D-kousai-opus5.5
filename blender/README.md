# Blender（Cycles）フォトリアル・パイプライン

`docs/GRAPHICS-PIPELINE.md` の契約に従い、ブラウザ版の書き出し（`blender/cache/scene.glb`・`meta.json`）から
Cycles で **GI ライトマップ**・**室内 HDR 環境マップ**・**静止画／360° パノラマ**を作るスクリプト群です。
GPU なし（CPU 4 コア）で動かす前提で、プレビュー（数分〜十数分）と最終品質（一晩）の 2 段構えにしています。

| ファイル | 役割 |
|---|---|
| `common.py` | シーン構築（読み込み・上階の積層・屋上・周辺街区）、マテリアルの物理ベース化、天空と太陽、カメラ、Cycles 設定 |
| `bake_lightmaps.py` | ライトマップ 3 枚（floor / ceil / wall）と `lightmaps.json`、`env_interior.hdr` |
| `render.py` | ショット表（静止画 18・パノラマ 6）のレンダーと `renders.json` |
| `verify.py` | 太陽・天空の向き、南面の日射、ライトマップ UV の向きの実測検証 |
| `calibrate.py` | 照度の実測（机上面プローブのベイク）。LED の輝度を 750 lx に合わせるのに使う |
| `run_final.sh` | 最終品質の一括実行（検証 → ベイク → 全ショット） |

中間ファイル（EXR・PNG・ログ）は `blender/out/`（git 管理外）。Blender 本体の大量の出力（Cycles の進捗・glTF の INFO）は
`blender/out/blender.log` に逃がしているので、端末には各工程の要約だけが出ます。

## 1. セットアップ

```sh
uv venv --python 3.11 .venv-blender
uv pip install --python .venv-blender/bin/python bpy==4.5.14 Pillow numpy
```

- `bpy` は Blender 4.5.14 LTS のモジュール版。Cycles（CPU）と OpenImageDenoise を含む。EEVEE は GPU がないと動かないので使わない。
- 入力はリポジトリ直下で `npm run dev` → `node scripts/export-scene.mjs` が書き出す `blender/cache/scene.glb`・`meta.json`。
  レイアウトを変えたら書き出し直し、ライトマップも焼き直す（`meta.json` の `lightmap.hash` が変わる）。

## 2. 使い方

```sh
PY=.venv-blender/bin/python

$PY blender/verify.py                              # 向き・位置・天空光の偏りの検証（約 2 分）
$PY blender/calibrate.py                           # 照度の実測（約 1 分）

$PY blender/bake_lightmaps.py --quality preview    # ライトマップ（半分の解像度・16 spp）＋ env_interior.hdr（8〜12 分）
$PY blender/bake_lightmaps.py --quality final      # 最終品質（約 4 時間）
$PY blender/bake_lightmaps.py --quality final --atlases wall --no-env   # 一部だけ焼き直す

$PY blender/render.py --list                       # ショット一覧
$PY blender/render.py --shots it-south,soc --quality preview
$PY blender/render.py --shots all --quality final   # 約 13〜14 時間
$PY blender/render.py --shots ext-se-day --quality final --samples 256 --scale 0.5   # 試し描き（blender/out/renders/trial/ に PNG だけ。同梱画像・renders.json・原寸は変えない）
$PY blender/render.py --resave                     # 中間 PNG から JPEG・サムネイルを作り直す（縮小幅を変えたときなど。PNG の寸法が renders.json と違うショットは飛ばす）

bash blender/run_final.sh                          # 最終品質の一括実行（約 18 時間、ログは blender/out/*.log）
```

- `--samples N`：サンプル数を上書き。`--scale S`：解像度倍率（`render.py` は品質プリセットの解像度にさらに掛ける。
  `bake_lightmaps.py` は契約サイズに対する倍率で、小さく焼いた結果は契約サイズに拡大して書き出す）。
- `renders.json`・`lightmaps.json` は部分実行でも該当項目だけ更新する（`lightmaps.json` はハッシュが変わると作り直す）。

## 3. 出力（契約 §3〜§5）

### ライトマップ `src/assets/baked/`

| ファイル | サイズ | 内容 |
|---|---|---|
| `lm_floor.webp` | 4096×2048 | 床（平面投影、北が上） |
| `lm_ceil.webp` | 4096×2048 | 天井（平面投影、北が上） |
| `lm_wall.webp` | 4096×4096 | 壁・柱のチャート（約 63 px/m） |
| `lightmaps.json` | | `hash`（`meta.json` から）、各アトラスの `file / w / h / scale`、`encoding: srgb8`、`quality`（preview / final）、`bake`（サンプル数・秒・統計）、`env` |
| `env_interior.hdr` | 1024×512 | IT 執務エリア（南）中央 three (25, 1.55, 14.5) の正距円筒 Radiance HDR（10:30、太陽あり） |

- **焼き込む光**：Diffuse の Direct＋Indirect（色なし）＝白い拡散面の輝度。天空光（Nishita、太陽ディスクなし、10:30 の分布）と室内照明。
  **直射日光は焼かない**（ブラウザ側で時刻に応じて与える）。上階の代わりに 3F スラブの蓋、家具・人物・周辺街区は遮蔽物として残す。
- **値**：画素 p（sRGB をデコードした 0〜1）× `scale` = ベイク値。照度 E = π × ベイク値 × 1,000 lx（単位は §5）。
  `scale` は有効画素の最大チャンネルの 99.5 パーセンタイル（それ以上は 1.0 に飽和、約 0.5% の画素）。
- **UV**：v は画像上端 = 0（Blender の画像をそのまま上から書き出す）。`verify.py` で実測確認済み（§7）。
- **予約ブロック**（`meta.json` の `lightmap.atlases.*.dummy`）と、どの UV も参照しない領域は有効画素の中央値で塗る。
- **手順**：アトラスごとに対象メッシュ（`meta.json` の `lightmap.meshes`、2F の原本）を 1 オブジェクトに結合 →
  `UVMap.001` へベイク（余白 8 px 相当、EXTEND）→ OIDN（コンポジターの Denoise、HDR・Accurate）→ 予約ブロック塗り → WebP（品質 92）。
  結合するのは、別オブジェクトのまま同じ画像へ焼くと余白の拡張が隣のメッシュの画素を上書きするため。
- **env_interior.hdr**：three.js の `equirectUv` と同じ並び（u = 0.5 が +X 東、u = 0.75 が +Z 南、上端が天頂）なので、
  回転なしで `scene.environment` に使える。値は線形（単位は §5）で、書き出し後に読み戻して EXR と一致することを確認している。

### 静止画・パノラマ `src/assets/renders/`

- レンダー解像度は静止画 1920×1080、パノラマ 4096×2048（正距円筒）。ここに置くのはブラウザに同梱する縮小版で、
  静止画 `<id>.jpg`（1600 px 幅、JPEG 品質 85）と `<id>_thumb.jpg`（480×270）。
- パノラマ `pano_<場所>.jpg`（3072 px 幅、品質 82）と `pano_<場所>_thumb.jpg`（480×240）。`renders.json` の `id` は `pano-<場所>`
  （静止画の `id` と重ならないように）。画像中央 = `heading`（北から時計回りの方位、プリセットの向き）、右へ時計回り、上端 = 天頂。
- final 品質を原寸（`--scale 1`）で描いたときだけ、原寸の JPEG（品質 92、4:4:4）を `docs/renders/` にも保存する（ファイル名は同梱版と同じ。静止画は `<id>.jpg`、パノラマは `pano_<場所>.jpg`。パスは renders.json の `original`）

- `renders.json` は契約の項目（`id, kind, title, preset, file, thumb, w, h, samples, seconds, sunHours, note`）と
  `webW`・`webH`（同梱画像の寸法。`w`・`h` はレンダー解像度）、`original`（原寸を保存したときのパス）に加えて
  `variant`・`ev`・`quality`、静止画は `camera`（three.js の pos/target/fov と 2 点透視のシフト量）、
  パノラマは `pos`・`heading`・`clearance`、平面図は `ortho`（中心・幅・高さ m、上 = 北）を持つ。

## 4. シーン構成（`common.build_scene`）

- **座標**：three.js (x=東, y=上, z=南) → Blender (x, −z, y)。Blender の +Y が北。2F の床仕上げ面が z = 0。
- **2F**：glTF の `L_structure / L_ceiling / L_eaves / L_furniture / L_people` をコレクション `F2`（下位に `F2_structure` など）へ。
- **上階**：3F〜12F は `F2` のコレクションインスタンスを 4.5 m ごとに積む。偶数階は東西反転して、ガラス越しの人・家具に変化を付ける
  （外周・コアは東西対称なので外観はそろう）。13F 相当の屋上スラブ・パラペット・塔屋（頂部 = 地上 62.166 m、Blender z = 56.566）・
  設備目隠しルーバー・冷却塔を外装マテリアルで追加。`L_upper`（半透明のゴースト）は非表示。
- **室内のショットとベイク**では上階インスタンスを隠し、**3F スラブだけの蓋**（`Cap`）で 2F を閉じる。
  上階の照明がスラブ越しに光源サンプルを奪ってノイズが増えるため（2F の窓に入る天空光は上階に遮られないので結果は同じ）。
- **1F**：`L_site` のポディウム・外構・街路樹をそのまま使う。
- **周辺街区**：ゴーストの `ghost.city` を箱ごとの独立オブジェクトにして、階・マリオンの格子と一部点灯した窓を持つ外装マテリアルを付ける。
  概略の箱なので**直射日光の影は落とさない**（ブラウザ版と同じ。影を落とすと高さ 88 m の箱が 10:30 に南面を丸ごと日陰にする）が、
  **天空光・反射光は遮る**。窓の発光は見た目だけで光源としてはサンプルしない。外観ショットではカメラを含む箱と、カメラから建物への視線を遮る箱を隠す。
  - 仕組み：`city` マテリアルは「影の光線（Light Path の Is Shadow Ray）で、向きが太陽方向 ±0.5° 以内」のときだけ Transparent になる
    （太陽ランプの角半径は 0.265°）。太陽の向きと有効・無効は `set_variant` が設定し、太陽ランプのない `bake`・`night` では無効。
    天空光・室内照明の影の光線と、カメラ・反射の光線に対しては不透明。
  - 箱を `visible_shadow = False`（すべての影の光線から外す）にしてはいけない。天空の光源サンプリング（窓のポータル）の影の光線だけが
    箱を素通りし、箱に当たる BSDF サンプリングと MIS で混ざって、室内の天空光が 1.9〜3 倍に偏る（以前の実装。§7 の `sky` 検証で検出できる）。
    修正前後の `calibrate.py` の比較では、day − bake（直射日光の寄与）も修正前のほうが 80〜270 lx 小さかった。偏りの大きさが
    光源選択の確率（太陽ランプの有無）で変わり、`day` と `bake` で天空光の値がそろっていなかったためと考えられる。
  - Cycles の影のリンク（太陽ランプの `light_linking.blocker_collection` に街区を EXCLUDE で入れる）でも同じことができるが、CPU では遅い。
    64 spp・同じ負荷での実測：`ext-se-day` 34.6 → 65.6 秒（CPU 時間 121 → 156 秒。スレッドの使用率も下がる）、`it-south` 51.4 → 61.1 秒。
    このシェーダー方式は 34.7 秒・52.3 秒で、実装前とほぼ同じ。影のリンクとの違いは 2 つ：太陽の円錐（約 2.4×10⁻⁴ sr、太陽ディスクなしの天空）の
    天空光の影の光線も素通りする（無視できる大きさ）。BSDF サンプリングで箱の向こうの太陽ランプに当たる寄与は箱に遮られる。
    拡散面では太陽ランプの BSDF 側の MIS 重みがほぼ 0 なので影響はないが、鏡面（ガラス・金属）に映る太陽のきらめきは、
    太陽との間に箱があると写らない（修正前の実装も同じ）。
- **ポータル**：2F の各カーテンウォール面（南・東・西・北の東西ウイング）に室内向きのポータルを置き、天空光のサンプリングを窓に集中させる。

## 5. 照明と校正

### 単位

放射照度 1.0 ≒ 1,000 lx、輝度 1.0 ≒ 1,000 cd/m²。Nishita 天空の既定スケールに合わせた近似です
（実測：快晴・太陽高度 49.7° の水平面天空照度 ≒ 9.2、太陽ディスクを含めると ≒ 104）。

### Cycles 設定（`common.setup_cycles`）

CPU、ライトツリー、適応サンプリング（最終 0.02）、OIDN（アルベド＋法線、Accurate）、パスガイディング（表面のみ。`it-south` のプレビューで、同じサンプル数での
ノイズの指標が約 9% 減・所要が約 25% 増で、時間あたりではほぼ互角。所要時間の実測はすべて有効の状態）、バウンス 最大 12・拡散 4・光沢 4・透過 8・透明 32、コースティクスなし、
Filter Glossy 1.0、永続データ（同じバリアントのショットを続けて描くとき BVH を使い回す）。
ライトマップのベイクは拡散 4・光沢 2・透過 4・透明 16、間接光クランプ 10。

## 6. マテリアル（`common.RULES_EXACT` / `RULES_PREFIX`）

キーは three.js のマテリアル名（`#rrggbb` の派生は元のキーで規則を引き、glTF のベースカラー・テクスチャは残す）。
規則のないキーは読み込み時の Principled のまま（現状の書き出しでは 0 件）。

## 9. 既知の制限

- **最終品質で通して実行済み**（2026-09-29〜10-01）：ライトマップ 3 枚と室内 HDR（`lightmaps.json` の `quality: "final"`、
  所要 3 時間 14 分）と、全 24 ショット（`renders.json` の各項目が `quality: "final"`）。CPU 4 コア・競合なしの実測で、
  静止画 18 枚 計 6.0 時間（1 枚 8〜26 分）、パノラマ 6 枚 計 2.8 時間（1 枚 25〜31 分）。§8 の見積もり（競合あり）より速い。
  実行中にコンテナが回収されて止まった場合は、`render.py --shots remaining --quality final`
  （または `bash blender/run_final.sh resume`）で、final になっていないショットだけを描き直せる
- 12F のセットバック（北側ウイング上部のテラス）は再現していない。12F も 2F と同じインスタンス。上階はどれも 2F の複製（偶数階は東西反転）。
- 周辺街区は概略の箱。直射日光の影は落とさないが、天空光を遮り、反射光も計算する（SOC の北窓に入る反射光など）。外観ショットではカメラを含む箱と視線を遮る箱を隠す。
- 廊下・EV ホール・水回り・機械室・倉庫などにはダウンライト、階段室には廊下側のブラケット灯 1 灯を置いた（照明計画は推定）。
  シャフトには照明がないので、ライトマップでは暗い（黒に近い）。
- ライトマップは 99.5 パーセンタイルで正規化するので、明るい 0.5% の画素（バルコニー・窓際）は飽和する。
- 室内のショットとベイクでは上階の代わりに 3F スラブの蓋を使う。2F 室内の光は変わらないが、向かいのガラスに映る自分の建物の上階は写らない。
- ガラスは屈折なしの薄板（意図的。影の光線が通り、窓越しの光が正しく入る）。
- 夕景は Nishita（太陽高度 1.6°）を ×0.18 に暗くした見た目の調整で、薄明の物理再現ではない。`afternoon` バリアントは用意したがショット表では使っていない。
- 人物・樹木はブラウザ版の低ポリゴンのまま。葉はノイズで塊感を出しているが、近景では様式的に見える。
  レンズの目の前（静止画 2.5 m、パノラマ 1.5 m 以内）に立つ・歩く人物は隠す。座っている人は静止画では残し、パノラマでは 1.2 m 以内なら隠す。
  `ext-street` はカメラから 7 m 以内の街路樹（低ポリゴンの樹冠が画面の手前を覆う）を隠す。
- `blender/out/blender.log`（Cycles の進捗）は実行のたびに追記されるので、適宜消してよい。
